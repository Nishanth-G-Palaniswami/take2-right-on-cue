# Measurement: v1 on D3 and D4, five replies each

Written and committed before the replies were generated.

**Question:** how often does v1 (unchanged) follow up correctly on D3, and how often does it probe again on D4?

**Setup:** `prompts/v1.md`, `cases/dev/D3.jsonl` and `cases/dev/D4.jsonl`, `gpt-5.4-mini`, reasoning effort `none`, 5 independent samples per case. The settings match the earlier runs.

**Order:** Nishanth judges the ten replies blind and his sheet is committed before Claude reports any count.

## Counting rules (fixed before generation)

**D3: did the reply ask for the missing outcome?** (count out of 5)

- **Yes** if it asks how the situation ended, how it was resolved or turned out, or how the brother responded afterwards. It counts whether this is the whole question or part of one conversational request for the rest of the story.
- **No** if it asks only what the applicant or the team did, without asking about the result, or if it moves on.
- Replies asking "what did you do to resolve it" ask about actions, not the result, so they count as no. Each such borderline reply is quoted in the report so Nishanth can overrule the count.

**D4: did the reply ask again about the resolved incident?** (count out of 5)

- **Yes** if it asks any further question about the family story (its outcome, actions, feelings or lessons) instead of moving on.
- **No** if it acknowledges the answer and moves on to the advocacy question, or to another next step, without a question about the incident.

The two counts are reported separately, each reply's classification is quoted, and Nishanth's labels are shown alongside. Five samples from one model and prompt give a rough frequency, not a rate estimate.
